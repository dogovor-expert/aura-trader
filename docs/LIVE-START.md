# Боевой запуск Aura Trader — с чего начать

Дата: 2026-10-16. Система проверена на бумаге, самотест 10/10.

## Демо или реальные деньги?

Режим определяется именами бирж в конфиге стратегии, а не настройкой где-то в панели:

- `bybit_paper_trade`, `okx_paper_trade`, ... (суффикс `_paper_trade`) — **демо**, ордера
  идут в симулятор Hummingbot, реальный баланс не тратится.
- `bybit`, `okx`, ... (без суффикса) — **реальные деньги**: ордера уходят на биржу.

Прямо сейчас в панели **сверху зелёный баннер «ДЕМО — бумажная торговля»**. Как только
хотя бы одна биржа переключится на боевой коннектор, баннер станет красным
(«РЕАЛЬНЫЕ ДЕНЬГИ») или жёлтым («СМЕШАННЫЙ РЕЖИМ»). Проверить вручную:

- В `conf/scripts/multi_exchange_signal_poller.yml` есть ли `_paper_trade` у `name:` бирж.
- Тот же вопрос к маршрутам в `conf/scripts/cross_exchange_arbitrage.yml`.

Кнопка «Торговля: включена» в панели **не** означает реальные деньги — она лишь разрешает
ставить ордера. Реальность ордеров задаёт коннектор (см. выше).

### Тумблер «Демо / Реальные деньги» в панели

В карточке «Торговля: запустить / остановить» есть строка **Режим** и кнопка переключения.
Она сама правит имена коннекторов в активном конфиге и перезапускает стратегию:

- **«Переключить на реальные деньги»** — убирает суффикс `_paper_trade` у всех бирж
  (ордера пойдут на биржи). Кнопка **неактивна**, пока нет ни одного подключённого
  боевого коннектора (`conf/connectors/<биржа>.yml`): сначала добавь ключ (`hbot connect bybit`).
  Перед переключением показывает окно подтверждения.
- **«Вернуть в демо»** — добавляет суффикс `_paper_trade` обратно (бумажная торговля).

Переключение перезапускает стратегию, поэтому текущие виртуальные позиции закрываются
вместе со старым процессом. Делай это, когда торговля не в позиции.

## С чего начать (правильный порядок)

### Шаг 1. Одна биржа, а не девять

Подключай **Bybit** первой. Причины:
- самая ликвидная из доступных нам и стабильнее всех отвечает из этой сети;
- работает и в сканере пампов, и в арбитраже (маршруты bybit→okx и okx→bybit), и в сигнальной стратегии;
- на ней уже прошли все проверки на бумаге.

Bybit API в Hummingbot: `hummingbot create --connector bybit`, затем впиши ключи.
Ключи API: **без разрешения на вывод средств** (`Enable Withdrawal` — выкл). Тогда даже при
компрометации ключа деньги не увести.

### Шаг 2. Пополнить на маленькую сумму

- Минимум для проверки: **50–100 USDT** на Bybit.
- Сумма одного ордера сейчас 1 USDT (в панели: «Параметры торговли» → «Сумма ордера»).
- Проверь, что USDT пришли и видны в Hummingbot (`hummingbot balances`).

### Шаг 3. Переключить коннектор с бумаги на реальный

В `conf/scripts/multi_exchange_signal_poller.yml` у нужной биржи заменить
`name: bybit_paper_trade` → `name: bybit`. Остальные биржи оставить бумажными или выключить
(`enabled: false`) — иначе система попытается торговать там, где ключей нет.

### Шаг 4. Проверить на минимальном риске

1. Поставь сумму ордера **1 USDT**, `max_concurrent_orders: 1`, `max_total_exposure_quote: 5`.
2. В панели оставь торговлю **выключенной**, включи и посмотри, что сигналы приходят
   (колонка «Сигнал в Hummingbot», лог `signals.log`).
3. Нажми **«Запустить торговлю»**.
4. Дождись одного реального входа и одного выхода по стопу или тейку.
5. Смотри карточку «Доход и убыток» — сделки, P&L, профит-фактор.

### Шаг 5. Масштабирование

Только после того, как 20–30 сделок отработали по плану (стоп/тейк/время):
поднимай сумму ордера: 1 → 5 → 10 → 25 → 50 USDT, не перескакивая.

## Что уже защищает систему

| Защита | Где |
|---|---|
| Торговля выключена по умолчанию | файл `data/trading_control.json`, кнопка в панели |
| Стоп-лосс каждой позиции | из риск-плана оракула; если его нет — берётся 2% из конфига |
| Аварийный стоп портфеля | закрывает всё, если портфель ушёл ниже −3% |
| Выход по времени | 360 минут, чтобы капитал не замирал |
| Проверка чисел модели | выдуманные числа срезают уверенность до 0.2 → WAIT |
| Размер по волатильности | в шторм сделки меньше |
| Защиты арбитража | 8 проверок: глубина, комиссии, одна нога, спуфинг, лимиты… |
| Стоп по волатильности и тик | падение портфеля → выход |

## Честные ограничения

- Автоторговля по пампам **выключена**: сканер есть, исполнения нет — нет стоп-лоссов в исполнителе пампов.
- Стратегия «Спот против перпетуала» не написана (кнопка в каталоге заблокирована).
- Калибровка уверенности набирает статистику: после починки порога (2 п.п.) сигналы пошли,
  но для честной оценки нужно десятки закрытых сделок.
- Комиссии за вывод при ребалансировке могут съесть прибыль арбитража — считать заранее.
- `max_daily_loss_quote` и `min_free_quote` объявлены, но **пока не проверяются в коде** —
  это следующая задача перед реальными деньгами.
